HANDS-ON TASKS:

HARDWARE NOTE:
Splunk needs about 4 GB RAM and Wazuh 4-8 GB. If the machine is limited, build one SIEM fully (Tasks 1-2 or Task 3) and complete the other tool's room and documentation only.

1. Install Splunk:
Install Splunk Enterprise (free trial that reverts to Splunk Free, 500 MB/day) on a Linux VM or the host. Create an index named `lab`. Screenshot the login page and the empty index.

Your deliverable is a running Splunk instance with a dedicated `lab` index ready to receive data.

2. Ingest Logs into Splunk:
Install the Universal Forwarder on the Windows VM to send Security and Sysmon logs (use the free Splunk Add-on for Sysmon), and monitor `/var/log/auth.log` on Ubuntu. Verify with a search on `index=lab`.

Take screenshots of:
- The forwarder configuration
- A successful search returning events from `index=lab`
- The Sysmon and auth.log events appearing in the index

Document the ingestion flow: log source → forwarder → indexer → search head.

3. Install Wazuh:
Use the official quickstart script on a dedicated Ubuntu VM. Enroll the Ubuntu and Windows agents. Enable file integrity monitoring on a test folder, change a file and screenshot the alert.

Take screenshots of:
- The Wazuh dashboard after installation
- Both agents enrolled and reporting
- The file integrity monitoring alert triggered by your file change

4. Attack to Alert:
From Kali, run an SSH brute force with Hydra (20-word list) against your own Ubuntu VM, and an Nmap `-sS` scan. Find both in the SIEM. Screenshot the raw event, parsed fields and the alert.

For each attack, document:
- The attacker command used
- The raw event as it appears in the SIEM
- The parsed fields and what they represent
- The alert generated (if any) or the manual search that surfaces the activity

5. Detections:
Write 5 SPL searches:
- Failed logons per user from EventCode 4625
- PowerShell process creation from Sysmon Event ID 1
- New user account creation from EventCode 4720
- SSH failures per source IP
- Rare parent-child process pairs

Save 2 of these as scheduled alerts and build a 4-panel dashboard.

Write 1 custom Wazuh rule in `/var/ossec/etc/rules/local_rules.xml` (rule ID 100000 or higher) and test it with `wazuh-logtest`.

Take screenshots of:
- Each SPL search and its results
- The two scheduled alerts configured
- The 4-panel dashboard
- The custom Wazuh rule and its logtest output

Document each search: what it detects, which MITRE technique it maps to, and why it is useful for an L1 analyst.

6. Triage Notes:
Pick 3 alerts and write who, what, when, where, why, verdict (true or false positive) and next step for each.

Save the triage notes in the "Findings" folder.

7. Cheat Sheets:
Create two tables:

Table 1: "SPL Command - Meaning - Example" with at least 15 entries.

Table 2: "SIEM Alert - Likely Cause - First Check" with at least 10 entries.

Save both in the "Cheat Sheet" folder.
